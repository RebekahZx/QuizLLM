# QuizLLM

[![ci](https://github.com/RebekahZx/QuizLLM/actions/workflows/ci.yml/badge.svg)](https://github.com/RebekahZx/QuizLLM/actions/workflows/ci.yml)

An Android quiz app that writes its questions with an LLM. Type any topic ("Java generics",
"the French Revolution", "photosynthesis"), and the app fetches a fresh multiple-choice quiz
generated by Gemini, walks you through it, and shows your score.

The repo has two parts:

| Part | Tech | Folder |
|---|---|---|
| Android app | Java, Retrofit + Gson, Material, min SDK 26 | `app/` |
| Quiz server | Python, Flask, Gemini (`google-genai`) with a JSON response schema | `server/` |

## How it works

```
Sign up / log in  →  pick a topic  →  GET /getQuiz?topic=…  →  answer A–D  →  score
 (local account)                      │
                                      ▼
                         server/app.py asks Gemini for N questions,
                         constrained to a JSON schema, then validates them
```

- **Structured output.** The server asks Gemini for JSON matching a schema (question, 4
  options, answer letter) instead of parsing free text.
- **Validation.** `normalize_quiz()` drops anything the app can't show: not exactly four
  options, duplicate options, or an answer that isn't one of the options. It also converts an
  answer given as option text into its letter. If nothing valid is left, the app gets a clean
  `502` instead of a broken quiz.
- **The app.**
  - The quiz screen stays disabled until the questions arrive.
  - It skips malformed questions.
  - It tells you when the server can't be reached, instead of crashing.
- **Local accounts.** Accounts live on the device. Passwords are stored only as salted
  PBKDF2-SHA256 hashes (`util/PasswordHasher.java`), never in plain text.

## Run it

**1. Start the server**

```bash
cd server
pip install -r requirements.txt
export GEMINI_API_KEY=...          # free key: https://aistudio.google.com/apikey
python app.py                      # http://0.0.0.0:5001
```

**2. Run the app.** Open the project in Android Studio and run it on an emulator. The app
reaches your computer at `http://10.0.2.2:5001/`.

**On a real phone:** run the server on your computer, then:

1. Set `quizApiUrl=http://<your-computer's-LAN-IP>:5001/` in `gradle.properties`.
2. Add that IP to `app/src/main/res/xml/network_security_config.xml`. Plain HTTP is allowed
   only to the hosts listed there.

## Tests

```bash
cd server && python -m pytest -q tests      # 10 tests; Gemini is mocked, no key needed
./gradlew testDebugUnitTest                 # password hashing tests
```

GitHub Actions builds the APK and runs both test suites on every push.

## Changes in the latest revision

- **The backend was missing.** The app called a quiz server that wasn't in the repo. It's now
  in `server/`, with tests.
- **Passwords.** They were stored in plain text in SharedPreferences. They're now salted
  PBKDF2 hashes, and existing accounts are converted the next time you log in. Sign-up also
  checks email format and password length.
- **Crashes on the quiz screen.** It crashed if you tapped Next before the quiz loaded, or if
  the server returned an empty quiz or a question without four options. All three are handled.
- **Configuration.**
  - The server URL is set in `gradle.properties` instead of hard-coded.
  - Plain HTTP is allowed only to local development hosts, instead of everywhere.
  - Internal screens are no longer exported to other apps.
- **Housekeeping.** Stopped tracking Android Studio's `.idea/` settings, removed
  commented-out code, and added CI.

## Limitations

- **Accounts are on-device only.** There is no server-side authentication.
- **Quality depends on the model.** The server checks the quiz's *format*, not whether each
  answer is factually correct.
